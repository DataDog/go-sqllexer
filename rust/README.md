# Rust implementation

A behavioral port of the Go package at the repository root: same output, byte for
byte, including on malformed input. It is a **parallel implementation**, not a
binding — nothing here is called from Go, and the two are kept honest by the
differential harness in [`../harness`](../harness).

```sh
cargo test --workspace          # unit and parity tests
cargo build --release           # the runner and the load driver
../harness/harness parity       # both implementations over every corpus
```

## Layout

| Crate | Contents |
| --- | --- |
| [`sqllexer`](sqllexer) | The library: lexer, obfuscator, normalizer, metadata. No dependencies, no `unsafe`. |
| [`sqllexer-runner`](sqllexer-runner) | Harness tooling — the protocol runner (`src/main.rs`) and the load driver (`src/bin/bench.rs`). Not a supported artifact. |

Each module is a port of one Go file, and deliberately keeps its shape so the two
can be read side by side:

| Rust | Go | Notes |
| --- | --- | --- |
| `sqllexer/src/lexer.rs` | `sqllexer.go` | Scanner for scanner, including cursor arithmetic on invalid UTF-8 |
| `sqllexer/src/obfuscator.rs` | `obfuscator.go` | |
| `sqllexer/src/normalizer.rs` | `normalizer.go` | Normalization and metadata collection |
| `sqllexer/src/token.rs` | `sqllexer.go` | Discriminants match the Go `iota` values; the harness compares them numerically |
| `sqllexer/src/keywords.rs` | `normalizer.go`, `obfuscator.go` | Keyword tables, as a flat trie. Compared against the Go source by `harness/keywordparity` |
| `sqllexer/src/chars.rs` | `unicode` usage in `sqllexer.go` | Rune decoding and classification over raw bytes |
| `sqllexer/src/unicode_tables.rs` | Go's `unicode` tables | Generated by `sqllexer/gen/unicode_tables.go`; do not edit |

## Porting rules

Two rules explain most of what looks unidiomatic here:

- **Quirks are reproduced, not corrected.** Where the Go code has observable
  oddities — invalid UTF-8 advancing the cursor by three bytes, `strings.TrimSpace`
  trimming Unicode spaces, metadata sizes counting only first occurrences — the Rust
  side reproduces them and says so in a comment. Fixing one would be a parity
  failure.
- **Bytes, not `str`.** The Go API accepts arbitrary bytes and its behavior on
  invalid UTF-8 is part of the contract, so inputs and outputs are `[u8]`
  throughout.

Performance work is concentrated in reuse rather than in clever scanning: callers
hold a `Processor` (or an `Obfuscator`/`Normalizer` pair) per worker and the output
buffers are reused across statements. See
[`../harness/reports/benchmarks.html`](../harness/reports/benchmarks.html) for what
that buys.
